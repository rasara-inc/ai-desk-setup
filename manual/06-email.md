# 수천 통의 메일을 차근차근 정리하기

목표는 숫자를 0으로 만드는 것보다 **중요한 메일을 놓치지 않고 광고가 다시 쌓이지 않게 하는 것**입니다.
설치만으로 메일을 지우거나 구독을 해지하지 않습니다. 실제 계정과 정리 기준을 함께 정합니다.

## 첫 요청

```text
최근 30일 메일을 먼저 살펴보고, 답장이 필요한 중요 메일과 광고를 나눠 줘.
아직 삭제하거나 읽음 처리하지 말고 분류 기준과 표본을 보여 줘.
수천 통이면 작은 묶음으로 나눠 진행하고, 다음에 광고가 덜 오게 할 방법도 제안해 줘.
```

## 에이전트의 처리 순서

1. 계정·조회 기간·폴더를 확인하고 읽기 도구의 지원 범위를 확인한다. 수집한 범위와
   조회 한도·페이지 누락 가능성을 기록한다. 수천 통을 한꺼번에 읽었다고 추정하지 않는다.
2. 중요 / 답장 필요 / 광고 후보 / 불명확으로 나눈다. 보낸 사람·도메인·제목·날짜·이유와
   대표 표본을 표로 보여준다. 가능하면 본문까지 확인하며 미열람은 불명확으로 둔다.
3. 금융·세금(CRA)·이민(IRCC)·의료·학교·보험·법률·계약·영수증·청구·보안 경고·
   거래처·고객·사람과 주고받은 메일은 기본 보존한다. 광고 발신자도 주문 영수증을 보낼 수 있다.
4. 구체적인 실행 목록을 준비한다: 대상 message/thread ID, 기간, 건수, 처리 방식,
   예외, 구독 해지 대상, 복구 방법. 일반 매뉴얼에 개인 메일 본문을 복사하지 않는다.
5. 사용자에게 해당 묶음의 삭제(휴지통 이동), 보관, 구독 해지, 필터 생성을 구분해 승인받는다.
   이미 승인된 범위는 반복 확인하지 않고 진행한다. 불명확한 항목만 따로 묻는다.
6. 한 번에 작은 묶음으로 실행하고 원래 상태/변경 결과를 로컬 작업 기록에 남긴다.
   thread 단위 삭제가 중요 답장까지 포함하지 않는지 먼저 확인한다.
7. 다시 조회해 성공·실패·미처리를 구분한다. timeout이면 실행 여부를 먼저 확인한 뒤 재개한다.
   재시도 때문에 두 번 행동하지 않는다. 토큰·서명 URL은 기록하지 않는다.

## 광고가 다시 쌓이지 않게 하기

정상적인 광고는 메일 서비스의 내장 Unsubscribe 또는 확인한 발신자의 공식 구독 관리로
해지합니다. 광고 수신만 해지하며 유료 서비스·계정·거래 알림을 취소하지 않습니다.
수상한 스팸의 링크는 클릭하지 않습니다. 스팸 신고·차단은 별도 후보로 제시합니다.
구독 해지 성공 화면과 해당 서비스의 반영 지연 안내를 확인합니다. 아직 다시 안 왔다고
장기 차단 성공으로 단정하지 않습니다.

필터는 ‘모두 자동 삭제’보다 광고 라벨·보관처럼 복구하기 쉬운 방식으로 제안합니다.
조건을 기존 메일에 미리 조회해 영수증·보안 메일이 걸리지 않는지 확인합니다.
기존 메일에 소급 적용하는 옵션은 별도로 확인합니다.

휴지통을 비우거나 영구 삭제하지 않습니다. 서비스별 복구 기한은 현재 안내를 확인하며
보존해야 할 원본은 별도로 저장합니다. 읽음 여부·오래된 날짜는 삭제 허가가 아닙니다.
메일 발송과 답장 초안 작성도 구분합니다. 초안 완성만으로 보내지 않습니다.
